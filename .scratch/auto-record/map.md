# Automated screen + camera recording

Label: wayfinder:map

## Destination

A single `record` command, declared in this repo, that captures the 3440x1440 screen plus the Canon R5 over USB plus mic and desktop audio, live-composites the camera as a circle overlay, previews the feeds before and during the take, and writes one NVENC-encoded file to `/home/s1n7ax/Videos/Youtube/00 new/<timestamp> <description>`. The file is YouTube-uploadable after a trim in LosslessCut. No OBS, no kdenlive.

## Notes

- Domain: NixOS + home-manager config repo. Hyprland/Wayland, NVIDIA (legacy_580), PipeWire, single 3440x1440@144 monitor at scale 1.25.
- Every session: consult `/grilling` and `/domain-modeling`. Prototypes via `/prototype`, research via `/research`.
- Settled during charting:
  - Drop OBS entirely — one ffmpeg pipeline, nothing to configure by hand.
  - Record native 3440x1440; never crop or pad for 16:9.
  - Mic and desktop audio as two separate tracks, never mixed. *Ticket 07 kept both untouched and added a **third** track — the mix — because a plain YouTube upload reads only one.*
  - Preview both before the take (with a mic level meter, Enter to start) and during it.
  - Foreground process; Ctrl-C stops the take, then prompts for the description and renames the temp file. Timestamp format `2026-09-19 14-30-05`.
  - Trim by hand afterwards in LosslessCut — no re-encode, exports mp4.
- Planning map: tickets resolve decisions. **The map is clear and the build has landed** — `record` lives at `system/home-manager/applications/record/`.
- Hardware facts surfaced while charting: GPU is a **GTX 1060** — H.264 and HEVC via NVENC, no AV1. The R5 has **no UVC mode**; gphoto2 PTP live view is the only USB feed.
- Camera facts measured in ticket 12, on the real body: live view is **camera-paced, not poll-bound** — stills mode 960x640 3:2 @ 30 fps fixed, movie mode 1024x576 16:9 @ exactly the Movie rec quality rate (25.00P/50.00P/4K 25.00P all confirmed). Recording *resolution* never changes live-view geometry; only the rate follows. The feed carries **no overlays at all** and needs no menu setting to clean it.
- Desktop facts confirmed in ticket 05, the first ticket run on the real machine rather than `dev-vm`: Hyprland **0.55.4**, whose Lua dispatcher API replaced `hyprctl dispatch movewindowpixel exact ...`; `wf-recorder` and `pactl` are **not installed**; `wf-recorder` captures the full physical 3440x1440 despite the logical 2752x1152 region; the default sink is a **Bluetooth headset**. Ticket 11 then confirmed the audio names on the real machine and retired the `pactl` worry: nothing in the pipeline needs it.
- Audio facts measured in ticket 16: PipeWire **moves** an orphaned `-f pulse` capture to another source rather than ending it — a source that disappears mid-take silently swaps the track's contents, with no error, no EOF and a full-length file. `node.dont-reconnect`, `stream.dont-move` and `PULSE_PROP` all fail to forbid it, so pinning a name protects only the *start* of a take, never the middle.
- Encode settled in ticket 07, measured on the real desktop: **`h264_nvenc`, not HEVC** — Pascal's HEVC encoder is ~30% less efficient here *and* rejects B-frames, so the old OBS `jim_hevc_nvenc` profile was the wrong choice on this GPU. `yuv420p` is **forced** by `overlay_cuda`, which refuses 4:4:4. **Three** audio tracks, because a plain YouTube upload reads only one and LosslessCut cannot mix: track 0 is the mix, tracks 1 and 2 the untouched pair.
- Shape settled in ticket 06, measured on the real desktop: **one ffmpeg spans the whole session** (preflight preview and take alike — the preview fifo cannot survive a handover), the camera runs **movie @ FHD 25.00P** because stills mode powers itself off, and the take is **50 fps end to end**. Ticket 13's thermals are therefore load-bearing, not optional. SIGINT finalises every output of a multi-output ffmpeg — ticket 05's runaway was `-t` on one output, not a Ctrl-C flaw.
- Build note, measured while implementing: ticket 06's fallback mitigation for the geometry lock — pinning `-f mjpeg -video_size` — **does not exist**; the mjpeg demuxer has no such option and errors out. The headless warm-up burst is the only guard, which makes it load-bearing rather than one of three choices.

## Decisions so far

<!-- one line per closed ticket -->

- [R5 over USB: what feed can we actually get?](issues/01-r5-usb-video-feed.md) — no native UVC on the R5, so gphoto2 stays; `--capture-movie` is polled PTP live view emitting untimestamped MJPEG at roughly 1024x576, unpaced ~10-25 fps; pipe it straight into the compositing ffmpeg and drop the v4l2loopback hop.
- [Screen capture into ffmpeg on Hyprland + NVIDIA](issues/02-wayland-screen-capture-into-ffmpeg.md) — `wf-recorder --codec rawvideo --file pipe:1` is the only viable route (wl-screenrec needs VAAPI encode, which NVIDIA lacks; ffmpeg has no PipeWire input; kmsgrab needs DRM master); one unavoidable system-memory round-trip, then `hwupload_cuda → overlay_cuda → h264_nvenc` stays on-GPU at 60 fps.
- [Addressing mic and desktop audio from ffmpeg](issues/03-pipewire-source-addressing.md) — `-f pulse` is the only route (ffmpeg has no PipeWire input); desktop audio via `@DEFAULT_MONITOR@` or a resolved `pactl get-default-sink` + `.monitor`; the mic must be pinned to a concrete node name or a headset plugged in mid-take silently takes over; concurrent metering during recording is safe.
- [The circle: how it looks and where it sits](issues/04-circle-overlay-prototype.md) — 540px circle, bottom-right at `overlay=2860:860`, 3px feather plus a 6px `#89b4fa` ring (the ring is required — with no ring the circle vanishes over a dark pane); mask is a static PNG through `alphamerge`, never `geq`, which benchmarked 8.3x more expensive and cannot hold 60 fps on CPU; all constants, no flags.
- [Preview that costs no frames](issues/05-live-preview-prototype.md) — the `split` branch costs **zero** dropped frames on both overlay paths (900/900 at 60 fps, measured on the real desktop); preview goes to a separate `ffplay` over `-f fifo` with `drop_pkts_on_overflow` and **never** `attempt_recovery` — a slow reader otherwise collapses the take to 3 fps and `attempt_recovery` hangs past SIGTERM; ffmpeg's `-f sdl` output silently never opens a window on Wayland; and the preview window hides inside the circle's **381px inscribed square**, where the overlay paints over it and it never reaches the file.
- [Does overlay_cuda carry alpha on the GTX 1060?](issues/14-overlay-cuda-alpha.md) — alpha survives and is genuinely blended: the composite is a feathered disc, not a 540x540 square (proved with pure-colour probes, 1.6% RMSE against the CPU reference), and `-v verbose` shows no `hwdownload` — `h264_nvenc` takes CUDA frames directly. Both paths are **NVENC-bound** at ~140 fps (2.3x headroom at 60); the GPU path wins on CPU given back (~2.2 ms/frame), not throughput, so the CPU `overlay` (~0.73 ms/frame here, not dev-vm's 18) stays a viable fallback.
- [Confirm the real audio source names on the desktop](issues/11-confirm-audio-device-names.md) — mic is `alsa_input.usb-fifine_Microphones_fifine_Microphone_REV1.0-00.analog-stereo`, desktop is `bluez_output.58_18_62_1F_32_D3.1.monitor` (both proved with a live `-f pulse` capture); no dedup counters — the `.1` is the profile's device index and survives an AAC/SBC/HFP switch; `pactl` is **not needed** (`pw-metadata -n default` covers preflight); but `@DEFAULT_MONITOR@` is unsafe here — with the headset off the default falls through to a GPU HDMI monitor nothing plays to, silently and at 8 channels → ticket 16.
- [Measure the R5's actual live-view stream](issues/12-measure-real-r5-stream.md) — stills mode is **960x640 3:2 @ 30.02 fps**, movie mode **1024x576 16:9 @ the Movie rec quality rate** (50.00P → 50.10 fps measured); baseline JPEG `yuvj422p`, ~96-118 KiB/frame, 19.7-42.7 Mbit/s; feed is clean of AF boxes, crop bars and info even with Servo AF on, so nothing to configure; `liveviewsize` must stay **Large** or the source quarters to 512x288; and libgphoto2 #567 is real — 1-2 stale-geometry frames after any mode change make ffmpeg's mjpeg demuxer **lock the whole take to the wrong size**, which `-probesize` cannot fix → ticket 06.
- [One ffmpeg, or a supervisor over several?](issues/06-pipeline-shape.md) — **one ffmpeg for the whole session** under a thin spawn-and-reap supervisor; the preview fifo cannot survive a preflight→take handover (reader locks to stream 1's params; writer 2's timestamps restart at 0), so there is no handover — the file rolls from the first preview frame and **Enter is a marker, not a switch**; camera is **movie @ FHD 25.00P** (stills powers itself off), output is **50 fps** throughout for an exact 2:1 camera cadence; `-use_wallclock_as_timestamps 1` on both pipes, since a declared `-framerate 25` against the real 25.04 drifts the circle ~3.8 s behind audio over 40 minutes; `eof_action=pass` so a dead camera removes the circle rather than freezing it (proved on the 1060: 36.9 dB vs a clean reference); SIGINT→10s→SIGTERM→3s→SIGKILL, safe only because mkv survives SIGKILL (3439/3442 frames); writes `<timestamp> UNTITLED.mkv` straight into the destination folder and renames in place, with orphans named on the next run.
- [NVENC settings and a container for two audio tracks](issues/07-encode-and-container.md) — `h264_nvenc -preset p4 -tune hq -rc vbr -cq 23 -b:v 0 -pix_fmt yuv420p -g 100 -bf 3 -spatial-aq 1 -aq-strength 8 -rc-lookahead 20` in mkv at 50 fps; **HEVC loses on this Pascal GPU** (~30% less efficient at matched quality, and `-bf 3` hard-fails — no B-frames before Turing), so the old OBS `jim_hevc_nvenc` profile goes; **`yuv420p` is forced** — `overlay_cuda` rejects 4:4:4 outright; `-g 100` because the GOP *is* LosslessCut's trim granularity (1 s costs +82%, 2 s +27%); and **three AAC tracks** — 0 = `amix=normalize=0:weights=1 0.35` (the only track YouTube reads), 1 = mic **mono** 96k, 2 = desktop 192k, labelled with both `title` and `handler_name` so the names survive the mp4 export; whole graph runs 111 fps, 2.2x headroom at 50.

- [What counts as "desktop audio", and what does preflight do when the default sink isn't it?](issues/16-desktop-audio-target.md) — desktop audio is the **monitor of whatever sink is default at preflight**, resolved once with `pw-metadata -n default`, not a pinned name; preflight **refuses** if it resolved to `alsa_output.pci-0000_05_00.1.pro-output-*` (the four GPU HDMI monitors are the only wrong fallthrough on this machine, and the 8ch `s32le` shape change) and **displays** the resolved name beside the mic meter, while zero-streams and first-second-RMS gates are rejected because silence at preflight is normal; the mic's pinned name is checked in `pw-dump` so a profile switch fails early with a named message instead of a generic pulse error mid-warm-up; a mid-take move **warns loudly with a wall-clock timestamp and never kills the take** (ticket 06's take-is-precious rule), one watcher covering both streams; and `default.configured.audio.sink` stays **unpinned** — a configured default that doesn't exist falls through to the same GPU monitors anyway.

- [LosslessCut into the config](issues/09-losslesscut-packaging.md) — the attribute is **`losslesscut`** (3.68.0, cached for x86_64-linux at 17.3 MB), in `packages.nix` behind `features.productivity.video-production.screen-capture.enable`; not `losslesscut-bin`, which is four minors behind on this channel; `kdenlive` stays commented out and **OBS stays declared until `record` has made a real take** — deleting the fallback before the replacement has been used once is the wrong order.

- [Where the record command lives in this repo](issues/10-packaging-shape.md) — its own directory `applications/record/`, **Python under `runCommand` + `makeWrapper`** exactly as `img-crop` and `voice-indicator` already are, `callPackage`d from `screen-capture.nix`; **not a shell script** — separate process sessions, a timed signal ladder over one of four children, two pipes plumbed by file descriptor, a JPEG header parser and a `pw-dump` poll loop are untestable in shell and are 98 headless tests in Python; one command (`camera-connect` untouched, dead but out of scope); **every tunable a constant in `config.py`** — no module options, no config file, no flags but `--check` (preflight only, no take); **no keybind**, because the command asks two questions on the terminal; and the script creates `~/Videos/Youtube/00 new` itself.

- [What goes in the 381px HUD, and is it worth having](issues/15-under-circle-hud.md) — the HUD is the **preview window and nothing else**: the whole composite at **340x142** (the screen's aspect at the HUD's width, not ticket 05's measuring square), so the circle is in it and `eof_action=pass` removing the circle is visible at a glance — the one failure a bare camera preview would miss; the **mic meter moves to preflight in the terminal**, with the resolved desktop source beside it, because drawing text into 340 px needs a second ffmpeg for a signal whose only response is to stop the take; **no recording indicator** — the pinned window is one; elapsed time and dropped frames stay on ffmpeg's stderr.

## Not yet specified

- Mic **noise suppression** — ticket 07 settled gain and channel count (mono, `weights=1 0.35` on the mix) and left the raw tracks untouched, so what remains is only whether the pipeline should denoise.
- Whether `weights=1 0.35` and the mic **mono** downmix hold up on a take with real speech — both were set from a quiet-room measurement, so the first real take is the check.
- Ring colour is hardcoded `#89b4fa` — whether it should track the system theme instead.
- Hyprland's `screencopy` permission now defaults to ASK and would prompt `wf-recorder` on every run — inert today only because this repo never sets `ecosystem.enforce_permissions`. Whether to pin that explicitly so a future Hyprland update cannot break unattended recording.
- HDMI plus a capture dongle as the fallback path. **Ticket 12 largely defused this**: 576-640px of source height into a 540px circle is near 1:1, not the severe upscale feared. Revisit only if the composited circle actually looks soft.

## Out of scope

- The trim itself — done by hand in LosslessCut.
- Thumbnails.
- Uploading to YouTube.
- **v4l2loopback and the loopback device** — [Load v4l2loopback without an interactive sudo](issues/08-v4l2loopback-without-sudo.md), closed. Ticket 06 settled that one ffmpeg reads `gphoto2 --capture-movie` straight off a pipe, so no loopback device is ever created. The pre-existing `camera-connect` script that does `sudo modprobe` becomes dead code once `record` lands, but deleting it is repo tidying, not part of this route.
- **Multi-take sessions** — several takes back to back without re-running preflight. Ruled out in [One ffmpeg, or a supervisor over several?](issues/06-pipeline-shape.md): the warm-up is ~2 s and the camera can change mode between takes, so the friction is small, while supporting it turns the supervisor into a state machine and reintroduces the restart problem the single-ffmpeg shape exists to avoid. Revisit only if the friction proves real in use.
